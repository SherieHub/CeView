## User Flows & Interaction (The Frontend)

Module 3 is the **Content Studio** — a single-view, sequential workflow that takes a business profile and a target market and produces (1) culturally localised promotional captions for four social platforms, (2) AI-generated visual direction and shot lists, and (3) a multimodal compliance score against those outputs. The entire module lives inside `ceview/components/module-3/3.1-content-studio/ContentStudioView.tsx` and is reached by navigating to the `'content'` tab from the Market Radar "Plan Content" CTA or directly from the sidebar.

---

### Sub-Flow A — Content Generation & Caption Matrix (Submodule 3.1)

1. **On mount**: `ContentStudioView` immediately fires `api.generateContent({ market, businessName, description, categories, trend }, businessProfileId)` → `POST /api/v1/content/generate`. A full-page spinner "Generating content from Gemini…" replaces the layout while the request is in-flight.
2. **Error states**: If generation fails, `<ServerErrorBanner>` appears with the structured `ApiError` code and trace ID. A fallback state message ("The content engine is unavailable") is shown below.
3. **Fallback pill**: When `content.source === 'fallback'` (Groq API key absent or unavailable), a gold "Demo content (Gemini offline)" pill appears in the header so operators know they are seeing curated template data.
4. **Content header**: Once loaded, a navy header card shows `"{Country} — {City} Profile"` derived from the `content.market` object returned by the API.
5. **AI Copywriting Matrix** (`AIContentMatrixPanel`): Three platform tabs render across the top — **Instagram**, **TikTok**, **Facebook**. Each tab displays 3 `CopywritingOptionCard` components, one per demographic archetype:
   - **Archetype 1 — "Witty, Trend-Conscious & High-Energy"** (Gen Z / Younger Demographic)
   - **Archetype 2 — "Formal, Educational & Value-Driven"** (Mature Planners / Family)
   - **Archetype 3 — "Storytelling, Immersive & Emotional"** (Aspirational / Experiential)
6. **Caption card features**: Each card shows the archetype name, the full caption text, and a live character counter vs. the platform limit. Clicking "AI Reasoning" expands a collapsible section with the 5 explainability fields returned by the LangGraph agent: `core_business_context`, `market_cultural_localization`, `psychological_elements`, `creative_tone_atmosphere`, `algorithmic_platform_architecture`. Cards can be edited inline — the `editOverrides` state map tracks changes per `"{tab}-{idx}"` key.
7. **Platform character limits** (enforced by the char counter):

   | Platform | Hard Limit | Optimal Target |
   |----------|------------|----------------|
   | Instagram | 2,200 chars | First 125 chars = hook |
   | Facebook | 63,206 chars | 2–3 paragraphs |
   | TikTok | 2,200 chars | 150–300 chars |

8. **Caption approval**: User clicks "Approve" on a card → `handleApproveOption(idx, text)` fires:
   - Updates `approvedIndices[activeTab] = idx` (gold ring appears on approved card).
   - Updates `approvedCaptions[activeTab] = text` (used later by compliance audit).
   - Stages the text in `stagedCaption` (auto-populates the `MediaCaptionManager` textarea).
   - **Fire-and-forget persistence**: `api.approveContent(businessProfileId, market)` → `POST /api/v1/content/approve`. This marks the content as approved in `tbl_localized_promotional_content`. The approval state is required by Submodules 3.2 and 3.3.

9. **Visual Direction Board** (`VisualDirectionBoard`): Rendered alongside the caption matrix. Displays `platform.guide[]` — a list of 5 curated visual direction tips per platform (e.g., "Aesthetic Mood Shot", "Apply warm golden filter", "4:5 portrait ratio"). These are market-specific and platform-specific, loaded from `gemini_client.get_platform_guides(market)`.

10. **Naver Blog tab**: A fourth platform injected into the API response. Content is **hardcoded Korean-language blog posts** — not generated by the LangGraph agent (which produces only the three main platforms). The two Naver options are: "힐링 스팟 스토리" (Healing Spot Story) and "여행 후기" (Travel Review).

### Sub-Flow B — Media Upload & Caption Staging (`MediaCaptionManager`)

1. **Drop zone**: Accepts `image/*` files via drag-and-drop or file picker. On file selection, `FileReader.readAsDataURL()` generates a `previewUrl` displayed as a preview card. Non-image files are silently ignored.
2. **Remove file**: "Remove" button clears `uploadedFile`, `previewUrl`, and resets the audit state.
3. **Caption textarea**: The approved caption (or manually typed text) sits in an editable textarea. This `stagedCaption` is what gets submitted to the compliance audit.
4. **Audit trigger**: The `SmartOptimizationBoard` activation auto-runs the audit when a file is uploaded and the audit toggle is on (`useEffect` dependency: `[hasFile, auditOn]`).

---

### Sub-Flow C — Compliance Audit (`SmartOptimizationBoard`)

1. **Toggle activation**: User clicks "Activate Audit" → `setAuditOn(true)`. If a file is already uploaded, `runAudit()` fires immediately.
2. **Caption validation**: `runAudit()` first checks `stagedCaption` — if empty, shows `'Add a caption before running the audit. [MOD3_COMPLIANCE_VALIDATION]'` and aborts.
3. **API routing decision** (based on whether `businessProfileId` is set):
   - **With profile ID** → `api.evaluateComplianceFull(payload, businessProfileId)` → `POST /api/v1/compliance/evaluate-full-json` → Full **CAS + VAS + HCS → OMCS** pipeline.
   - **Without profile ID** → `api.evaluateCompliance(payload)` → `POST /api/v1/compliance/evaluate-json` → Basic Groq single-score path.
4. **Simulated progress bar**: A `setInterval` timer (160 ms interval) advances `auditProgress` by random 4–11 point increments. At 100%, a 450 ms delay then sets `auditDone = true`. The API call and the timer run **concurrently** — the progress bar provides UX feedback while the real HTTP request completes independently. Six labeled steps display sequentially as progress passes their thresholds (at 15%, 35%, 55%, 75%, 90%, 100%).
5. **Compliance results panel** (when `auditDone && compliance`):
   - **`ComplianceGauge`**: Circular gauge displaying the OMCS score (0–100).
   - **`InterpretationBadge`**: Color-coded label based on OMCS:
     - `90–100` → **Excellent Alignment** (green) `✦`
     - `80–89` → **High Compliance** (blue) `✓`
     - `70–79` → **Moderate Revision Required** (gold) `⚠`
     - `< 70` → **Significant Revision Required** (red-orange) `✕`
   - **Sub-score chips** (only when full pipeline ran via `businessProfileId`): Three colored chips — `CAS`, `VAS`, `HCS` — each with green/gold/red coloring by score band (≥80, ≥60, <60). Tooltip on hover explains the sub-score's source.
   - **OMCS formula display**: `OMCS = (0.35 × CAS) + (0.45 × VAS) + (0.20 × HCS)` shown as labeled text below the chips.
   - **`FeedbackList`**: Two-column layout — "What Works" (aligned items, green check icons) and "What Needs Improvement" (gaps, red X icons).
   - **"Detected Mismatches" panel** (full pipeline only): Amber panel showing mismatches between the submitted caption and the approved creative direction context.

These display connection status (verified/unverified icons) and are UI scaffolding for future social API integrations — no live API calls are made from this panel.

## System Workflow & Sequence (The Bridge)

Module 3 has three sequential transactions — each builds on the previous. Submodule 3.2 requires 3.1 to have produced approved content. Submodule 3.3 requires both 3.1 and 3.2 context to run its full pipeline.

---

### Request Lifecycle 1 — Content Generation (Submodule 3.1)

**Trigger**: `ContentStudioView` mounts → `POST /api/v1/content/generate?profileId={UUID}`.

1. `ContentController.generate()` delegates to `ContentGenerationService.generate()`.
2. **DB enrichment (FR3.1)**: When `profileId != null`, loads `BusinessProfile` from `tbl_business_profile`. DB values **override** the HTTP request body — ensuring the AI prompt uses the verified, persisted identity rather than user-supplied fields from the frontend.
3. **Forecast context (FR3.4)**: `buildForecastContext(profileId, market)` queries the latest `ForecastResult` (4-week horizon) + `MarketScore` from Module 2 tables. Extracts: `predictedDemand`, `forecastConfidence`, `mapeScore`, `marketScore`, `spikeIndicator`, `seasonalityScore`, `gdpGrowth`. This context is injected into the FastAPI prompt.
4. Builds enriched payload → `ai.generateContent(payload)` → `POST /internal/content/generate` to fastapi-sbert (30 s timeout).
5. FastAPI runs the **LangGraph caption generation pipeline** (see Engine section) → returns `ContentResponseDto`.
6. **Persistence (FR3.10)**: For each platform in `dto.captions()`, creates one `LocalizedPromotionalContent` row in `tbl_localized_promotional_content` (per-platform: caption text, content direction, framework, source). Writes `ContentGenerationLog` audit entry.
7. Returns `ContentResponseDto` as `200 OK`.

---

### Request Lifecycle 2 — Content Approval

**Trigger**: User clicks "Approve" on a caption card → `POST /api/v1/content/approve?profileId={UUID}` with body `{ "market": "korea" }`.

1. `ContentController.approve()` delegates to `ContentApprovalService.approveForMarket(profileId, market)`.
2. Finds all `LocalizedPromotionalContent` rows for `(profileId, market)` where `approval_status = false`.
3. Sets `approval_status = true`, stamps `approved_at = now()`.
4. Returns list of `approvedIds`. This approval flag is the **dependency gate** checked by Submodule 3.2 before generating creative direction.

---

### Request Lifecycle 3 — Creative Direction (Submodule 3.2)

**Trigger**: `api.generateCreative(profileId, market)` → `POST /api/v1/creative-direction/generate/{profileId}?market=`.

1. `CreativeDirectionController.generate()` delegates to `CreativeDirectionService.generate(profileId, market)`.
2. **UC-3.1 dependency check (FR3.11)**: `contentApprovalService.hasApprovedContent(profileId, market)` — queries `tbl_localized_promotional_content` for approved rows. If none → throws `IllegalStateException("missing_dependency")` → controller returns `400 { error: "missing_dependency", message: "Content from Transaction 3.1 must be approved...", redirect: "/content-studio" }`. This is the **A3 alternative flow**.
3. `contentApprovalService.getApprovedCaptions(profileId, market)` — reads approved caption text from DB.
4. Loads `BusinessProfile` (categories, uniquenessScore) and `buildForecastContext()`.
5. Builds payload with `approvedCaptions[]` → `ai.generateCreative(payload)` → `POST /internal/creative/generate`.
6. FastAPI generates visual direction via Groq.
7. **Persistence (FR3.19)**: Saves `CreativeDirectionOutput` entity: `shotListRecommendations`, `visualRecommendations`, `lightingSuggestions`, `moodboardReferences`, `platformRecommendations`, `visualTone` (palette string). These are extracted from the JSON response and stored for use by Submodule 3.3's HCS Rule 6 and VAS computation.
8. Writes `CreativeDirectionLog` audit entry. Returns `CreativeDirectionDto`.

---

### Request Lifecycle 4 — Full Compliance Analysis (Submodule 3.3)

**Trigger**: `POST /api/v1/compliance/evaluate-full-json?profileId={UUID}` with body `{ caption, market, mediaName, mediaSize }`.

1. `ComplianceController.evaluateFullJson()` validates caption is non-blank → delegates to `ComplianceAnalysisService.analyze()`.
2. **Context retrieval (FR3.21)**:
   - `approvedCaptions = contentApproval.getApprovedCaptions(profileId, market)` (from 3.1).
   - `categories = profile.categoriesList()` from `BusinessProfile` (for HCS rule 1 tourism alignment).
   - `visualTone, shotListContext` from latest **approved** `CreativeDirectionOutput` (for HCS rule 6 and VAS context).
3. **Pipeline routing (FR3.30)**: `hasEnrichedContext = !approvedCaptions.isEmpty()`. If true → full CAS+VAS+HCS pipeline. If false → basic `ai.evaluateCompliance()` path.
4. `invokeFullPipeline()` → `ai.evaluateComplianceFull(payload)` → `POST /internal/compliance/evaluate-full` to fastapi-sbert. Payload includes: caption, market, approvedCaptions, categories, visualTone, shotListContext, mediaName, mediaSize.
5. If FastAPI returns 5xx or times out → **automatic fallback** to `invokeBasicEvaluate()` (FR3.30 graceful degradation).
6. **Persistence (FR3.28/FR3.29)**:
   - `revisionNumber = existing_max_revision + 1` (or 1 on first submission).
   - Saves `ComplianceEvaluationResult` with all sub-scores.
   - When `revisionNumber > 1`: additionally saves `ComplianceRevisionHistory` row (tracks resubmission lineage: original eval ID, caption, CAS score, OMCS, threshold).
7. Returns `ComplianceResultDto` with all sub-scores and explainability fields.

---

### Request Lifecycle 5 — Basic Compliance Path

**Trigger**: `POST /api/v1/compliance/evaluate-json` (no `profileId`, no enrichment).

1. `ComplianceController.evaluateJson()` calls `ai.evaluateCompliance(payload)` → `POST /internal/compliance/evaluate` → `gemini_client.evaluate_compliance()`.
2. Groq prompt evaluates the caption holistically: cultural fit, readability, hashtag strategy, destination tagging, emotional resonance, trigger words.
3. Returns: `{ score, aligned[], gaps[], source }` — no sub-scores (CAS/VAS/HCS unavailable without approved captions context).

## Background Processing & Algorithmic Logic (The Engine)

### Module 3 AI Stack Overview

Module 3 uses two separate AI clients operating in parallel layers:

| Component | AI Client | Model | Role |
|-----------|-----------|-------|------|
| Caption Generation Agent | `langchain_groq.ChatGroq` via LangGraph | `llama-3.3-70b-versatile` | Node 1 service filter + Node 2 caption matrix |
| Creative Direction | `openai.OpenAI` (Groq base URL) via `gemini_client` | `llama-3.3-70b-versatile` | Visual direction, shot list, moodboard |
| VAS (Visual Alignment Score) | `openai.OpenAI` (Groq base URL) via `gemini_client` | `llama-3.3-70b-versatile` | Multimodal caption-visual compliance evaluation |
| Basic Compliance | `openai.OpenAI` (Groq base URL) via `gemini_client` | `llama-3.3-70b-versatile` | Holistic single-score caption audit |
| CAS (Caption Alignment Score) | `SentenceTransformer` (E5) reused from Module 1 | `intfloat/multilingual-e5-base` | Cosine similarity vs. approved captions |
| HCS (Heuristic Compliance Score) | None — deterministic Python rules | N/A | 6-rule deterministic checker; always succeeds |
| Cultural Research | SerpAPI → curated templates fallback | N/A | Market-specific traveler behavior context |

### LangGraph Caption Generation Agent

The agent is defined in `app/agents/creative_director_agent/` and compiled as a `StateGraph` with exactly two nodes and a linear flow:

```
Entry Point
     │
     ▼
┌──────────────────────┐
│  Node 1              │
│  analyze_services    │  ← Filters business services into relevant vs. differentiators
└──────────────────────┘
     │   (always proceeds — no conditional branching)
     ▼
┌────────────────────────────┐
│  Node 2                    │
│  generate_platform_captions│  ← Produces 3-platform × 3-archetype caption matrix
└────────────────────────────┘
     │
     ▼
    END
```

**`SocialAgentState` (LangGraph typed dict):**

```python
{
  # Inputs (set by CaptionInputClass before ainvoke())
  business_name:        str          # from BusinessProfile
  business_description: str          # from BusinessProfile
  business_uvp:         str          # from BusinessProfile
  business_services:    list[str]    # categories from BusinessProfile
  market_category:      str          # first category or trend
  target_market:        str          # "South Korea" | "Japan" | "USA"
  forecast_context:     str          # pre-formatted multi-line string from Module 2
  research_context:     str          # pre-formatted multi-line string from SerpAPI/templates

  # Outputs (set by nodes during graph execution)
  relevant_priority_services: list[str]        # set by Node 1
  extra_additional_services:  list[str]        # set by Node 1
  final_captions:             dict             # set by Node 2
  source:                     str              # "groq" | "fallback"
}
```

---

#### Node 1 — `analyze_services` (Service Relevance Filtering)

**LangChain chain**: `service_analysis_prompt | ChatGroq | JsonOutputParser()`

**System prompt**: "You are an analytical brand strategist for a Cebu, Philippines tourism business. Sort all provided business services into two categories: `relevant_services` (directly related to the market category) and `unique_differentiators` (unexpected selling points that make the business stand out). Every service must appear in exactly one category."

**Input variables**: `{ market_category, business_services }` (all services from state).

**Output**: `{ relevant_services: [...], unique_differentiators: [...] }` which maps to state keys `relevant_priority_services` and `extra_additional_services`.

**Fallback** (LLM unavailable): All services passed as `relevant_priority_services`; `extra_additional_services = []`. The graph continues without error — Node 2 receives the unfiltered list.

**Purpose**: Separates core offerings (used in the primary marketing narrative) from unexpected differentiators (mentioned briefly to add uniqueness). Both sets are injected into the Node 2 prompt as separate template variables so the LLM knows which to lead with and which to weave in subtly.

**The 4 Caption Factors** force holistic caption construction across four dimensions simultaneously:
- **Factor 1 (Core Business Context)**: Tourism category metadata, unique services, UVP, and Cebu's destination-specific appeal.
- **Factor 2 (Market & Cultural Localisation)**: Native-language integration — Hangul for Korean (힐링여행, 호캉스, 세부여행); Kanji/Katakana for Japanese (絶景, 癒し, セブ島, 非日常); casual American English with FOMO vocabulary for USA.
- **Factor 3 (Psychological Vectors)**: Per-archetype emotional activation — Archetype 1 uses FOMO/urgency; Archetype 2 uses exclusivity/value; Archetype 3 uses escapism/tropical healing via the tension→threshold→release emotional arc.
- **Factor 4 (Platform Mechanics)**: Hard character limits, truncation windows, link policies, and hashtag counts strictly enforced.

| Archetype | Tone | Emoji | Psychological Vectors |

| Witty, Trend-Conscious & High-Energy | Playful, casual, punchy | High density | FOMO, social proof, excitement, urgency |
| Formal, Educational & Value-Driven | Respectful, authoritative | Minimal (📍 ✈️ 📅) | Exclusivity, security, value certainty |
| Storytelling, Immersive & Emotional | Cinematic, sensory, emotional arc | Moderate | Escapism, tropical healing, nostalgia |

### OMCS Compliance Pipeline — Full Algorithm (Submodule 3.3)

The **Overall Multimodal Compliance Score (OMCS)** is computed in FastAPI `compliance.py`'s `/evaluate-full` endpoint from three independent sub-scores:

```
OMCS = (0.35 × CAS) + (0.45 × VAS) + (0.20 × HCS)
```

**Weight rationale**:
- **VAS (45%)** carries the highest weight because visual alignment is the primary driver of ad effectiveness on social platforms — a caption that mismatches visual tone fails regardless of text quality.
- **CAS (35%)** rewards consistency with the AI-generated creative brief — ensuring the operator's caption stays in-brand.
- **HCS (20%)** provides a deterministic floor that can never be overridden by AI unavailability.

---

#### CAS — Caption Alignment Score (FR3.25.1)

`sentence_bert_scorer.compute_cas(submitted_caption, approved_captions)`

The same `intfloat/multilingual-e5-base` E5 model singleton loaded for Module 1 is **reused** here — no second model download or memory overhead.

**BERT path** (E5 model loaded):
```
Step 1 — Encode:
  all_texts = [submitted_caption] + approved_captions
  embeddings (n+1, 768) = model.encode(all_texts, normalize_embeddings=True)
  # L2-normalised unit vectors → dot product == cosine similarity

Step 2 — Compute max similarity:
  submitted_emb (768,)  = embeddings[0]
  approved_embs (n, 768) = embeddings[1:]
  similarities (n,)     = approved_embs @ submitted_emb
  max_similarity        = max(similarities)

Step 3 — Scale:
  CAS = clamp(max_similarity, 0, 1) × 100

# High CAS = the submitted caption is semantically similar to at least one
# approved AI-generated caption — operator stayed on-brief.
```

**Keyword fallback** (E5 model unavailable, FR3.30):
```
overlap_score  = (len(sub_words ∩ approved_words) / len(sub_words ∪ approved_words)) × 50
hashtag_score  = 15   if re.search(r"#\w+", submitted)
cta_score      = 10   if any(cta_pattern in submitted.lower())
length_score   = 25   if 80 ≤ len(submitted) ≤ 400
               = 15   if len > 40
               = 5    otherwise
CAS_fallback   = overlap_score + hashtag_score + cta_score + length_score
```

#### VAS — Visual Alignment Score (FR3.25.2)

`gemini_client.evaluate_compliance_multimodal(caption, market, approved_captions, visual_tone, shot_list_context, media_name, media_size)`

**Groq prompt evaluates 5 criteria** (model returns a weighted integer 0–100):
1. **Composition consistency** — does the caption imply visual framing aligned with the creative direction recommendations?
2. **Cultural appropriateness** — does the tone and language match the target market's traveler expectations?
3. **Visual tone alignment** — does the emotional atmosphere match the approved moodboard palette/style?
4. **Subject emphasis** — are the correct tourism subjects (healing, scenery, food) emphasised?
5. **Destination relevance** — is Cebu positioning clear and authentic?

**Prompt injects**:
- Submitted caption text.
- Up to 3 approved reference captions from 3.1.
- `visualTone` from 3.2 (moodboard palette string).
- `shotListContext` from 3.2 (first 400 chars of shot list JSON).
- `mediaName` and `mediaSize` (informational hint about uploaded media).

**Returns**: `{ vas, aligned[], gaps[], mismatches[], source }`.

**Deterministic fallback** (`_visual_fallback_evaluation(market)`):

| Market | Fallback VAS | Primary Gap |
|--------|-------------|-------------|
| Korea | 74 | No Korean hashtags; no golden-hour framing cues |
| Japan | 76 | Missing Japanese trigger words (絶景, 癒し) |
| USA | 71 | No explicit CTA; no FOMO framing |

#### HCS — Heuristic Compliance Score (FR3.25.3)

`sentence_bert_scorer.compute_hcs(caption, market, categories, approved_captions, visual_tone, media_name)`

Fully deterministic — no AI dependency. **Always produces a score** regardless of external service availability (FR3.30). Six independent rules contribute a fixed maximum weight:

```
Rule 1 — Tourism Category Alignment            20 pts (max)
Rule 2 — Target-Market Cultural Consistency    20 pts (max)
Rule 3 — Seasonal Appropriateness             20 pts (max)
Rule 4 — Promotional Tone Conformity          15 pts (max)
Rule 5 — Recommendation Adherence            15 pts (max)
Rule 6 — Caption-Visual Consistency          10 pts (max)
                                             ──────────────
                                         HCS = 100 pts (max)
```

**Rule 1 — Tourism Category Alignment (20 pts)**:
```python
category_words = set(tokenize(each_category))   # e.g. "Coastal & Island" → {coastal, island}
combined       = _TOURISM_TERMS | category_words  # 45 tourism/hospitality anchor terms
tourism_hits   = len(tokens(caption) ∩ combined)

if tourism_hits ≥ 3: score += 20    # well-aligned
elif tourism_hits ≥ 1: score += 12  # partially aligned
else: score += 0                    # off-brand
```
`_TOURISM_TERMS` includes 45 domain-specific words: resort, beach, island, dive, snorkel, spa, wellness, healing, nature, waterfall, adventure, cultural, heritage, food, cuisine, hotel, eco, retreat, tour, trip, travel, vacation, holiday, relax, sunset, sunrise, pool, villa, lodge, stay, destination, paradise, pristine, scenic, breathtaking, getaway, cebu, philippines, visayas, palawan, boracay, and more.

**Rule 2 — Target-Market Cultural Consistency (20 pts)**:
```python
signals = _MARKET_SIGNALS[market]    # per-market native-language keywords
market_hits = count(sig in caption.lower() for sig in signals)

if market_hits ≥ 2: score += 20
elif market_hits == 1: score += 12
elif market name in caption: score += 6
else: score += 0
```
Market signal dictionaries:
- **Korea**: `"세부 여행"`, `"힐링"`, `"호캉스"`, `"korea"`, `"korean"`, `"healing"`, `"k-travel"`, `"kdrama"`, `"wellness"`, and 6 more.
- **Japan**: `"セブ島"`, `"japan"`, `"japanese"`, `"nippon"`, `"zen"`, `"onsen"`, `"sakura"`, `"wabi"`, `"sabi"`, `"traditional"`, `"harmony"`, and 3 more.
- **USA**: `"usa"`, `"america"`, `"bucket list"`, `"paradise"`, `"adventure"`, `"surf"`, `"tropical getaway"`, `"dream vacation"`, `"wanderlust"`, and 3 more.

**Rule 3 — Seasonal Appropriateness (20 pts)**:
```python
_ANTI_TROPICAL = ["snow", "snowflake", "blizzard", "winter wonderland", "icy",
                  "freezing cold", "bundled up", "thick coat", "mittens",
                  "frostbite", "polar vortex"]
contradictions = count(term in caption.lower() for term in _ANTI_TROPICAL)

if contradictions == 0: score += 20   # no non-tropical language
elif contradictions == 1: score += 10 # one slip
else: score += 0                      # 2+ contradictions → disqualified
```
A Philippine tourism business should never reference non-tropical seasonal language (snow, winter, etc.). This rule protects against AI-generated captions that inadvertently use off-context seasonal vocabulary.

**Rule 4 — Promotional Tone Conformity (15 pts)**:
```python
_CTA_PATTERNS  = ["book", "visit", "explore", "discover", "experience", "join",
                   "escape", "plan", "reserve", "come", "don't miss", "see you",
                   "link in bio", "tap the link", "dm us", "→", "now", "today",
                   "limited", "exclusive"]
_POSITIVE_TERMS = ["amazing", "beautiful", "stunning", "breathtaking", "unforgettable",
                    "incredible", "magical", "serene", "peaceful", "vibrant", "luxurious",
                    "authentic", "unique", "pristine", "paradise", "hidden gem", "must-see",
                    "perfect", "ideal", "dreamy"]

has_cta      = any(pattern in caption.lower())
has_positive = any(term in caption.lower())

if has_cta and has_positive: score += 15  # fully promotional
elif has_cta or has_positive: score += 8  # partially promotional
else: score += 0                          # lacks promotional tone
```

**Rule 5 — Recommendation Adherence (15 pts)**:
```python
has_hashtag = bool(re.search(r"#\w+", caption))
good_length = 40 ≤ len(caption) ≤ 500        # compliant caption length range

if has_hashtag and good_length: score += 15
elif has_hashtag or good_length: score += 8
else: score += 0
```
Platform discoverability requires at least one hashtag. Caption length 40–500 chars is the recommended range balancing depth and readability.

**Rule 6 — Caption-Visual Consistency (10 pts)**:
```python
if visual_tone:
    vt_tokens = tokens(visual_tone)
    overlap   = len(tokens(caption) ∩ vt_tokens)
    if overlap ≥ 3: score += 10     # strong alignment with moodboard
    elif overlap ≥ 1: score += 6    # partial alignment
    else: score += 3                # visual tone present but unaligned
elif media_name:
    # Media uploaded but no creative direction exists yet
    word_count = len([t for t in tokens(caption) if len(t) ≥ 3])
    score += 8 if word_count ≥ 5 else (4 if word_count ≥ 2 else 0)
else:
    # Text-only submission (no media, no visual tone)
    score += 6 if len([t for t in tokens(caption) if len(t) ≥ 3]) ≥ 4 else 3
```

#### OMCS Composition & Thresholds

```
OMCS = (0.35 × CAS) + (0.45 × VAS) + (0.20 × HCS)
OMCS = clamp(OMCS, 0.0, 100.0)

# Example:
# CAS = 78.5 (BERT path, moderate similarity to approved captions)
# VAS = 82.0 (Groq: good composition, correct market signals, minor mismatch on subject emphasis)
# HCS = 65.0 (deterministic: no Korean hashtags -8pts, adequate tone)
# OMCS = (0.35 × 78.5) + (0.45 × 82.0) + (0.20 × 65.0)
#       = 27.475 + 36.900 + 13.000 = 77.375 → "Moderate Revision Required"
```

**Threshold interpretation** (`sentence_bert_scorer.interpret_omcs(omcs)`):

| OMCS Range | Label | Action |
|------------|-------|--------|
| 90 – 100 | **Excellent Alignment** | Content is ready for distribution |
| 80 – 89 | **High Compliance** | Minor refinements optional |
| 70 – 79 | **Moderate Revision Required** | Review gaps before publishing |
| 0 – 69 | **Significant Revision Required** | Substantial rework needed |

**Source label** (composite string for log correlation):
```
source = "cas:bert,vas:groq,hcs:rule-based"          # full pipeline
source = "cas:keyword-fallback,vas:fallback,hcs:rule-based"  # all fallback
```

The `score` field in the response (integer) equals `int(round(omcs))` when the full pipeline ran, making it backward-compatible with the basic path which returns a direct Groq integer.

### `AgentLLMModel` — Thread-Safe LLM Singleton

```python
class AgentLLMModel:
    _instance = None
    _lock = threading.Lock()   # prevents race conditions on first access

    def _initialize(self):
        from langchain_groq import ChatGroq
        self._model = ChatGroq(
            model      = "llama-3.3-70b-versatile",
            temperature = 0.7,              # creative temperature for caption writing
            groq_api_key = api_key,
        )
```

**Self-healing**: `get_model()` calls `_initialize()` again if `_model` is `None` — handles environments where `GROQ_API_KEY` is set after module import. Used exclusively by the LangGraph agent nodes (Node 1 and Node 2). The `gemini_client.py` uses a separate `openai.OpenAI(base_url="https://api.groq.com/openai/v1")` instance with `temperature=0.4` for the compliance and creative functions — lower temperature for more deterministic factual outputs.

## Technology Stack & Infrastructure

| Layer | Technology | Justification |
|-------|------------|---------------|
| **Frontend framework** | React 18 + TypeScript, Vite | Single view (`ContentStudioView`) owns all Module 3 state; `approvedIndices`, `approvedCaptions`, `compliance` are lifted to the view level so all panels share consistent state |
| **Caption matrix UI** | `AIContentMatrixPanel` + `CopywritingOptionCard` | Inline editing with `editOverrides` state map; per-card expand/collapse for AI reasoning metadata; character counter with platform-specific limits |
| **Agent framework** | LangGraph (`StateGraph`, `ainvoke`) | Two-node sequential workflow — service filtering (Node 1) then caption matrix generation (Node 2); async `ainvoke()` integrates naturally with FastAPI's async request handler |
| **Agent LLM** | `langchain_groq.ChatGroq` (`llama-3.3-70b-versatile`, temperature=0.7) | Higher temperature (0.7) for creative caption writing diversity; thread-safe singleton via `threading.Lock()` prevents concurrent initialization race conditions |
| **Groq client (compliance/creative)** | `openai.OpenAI` (Groq OpenAI-compatible API, temperature=0.4) | Lower temperature (0.4) for deterministic factual evaluation; `response_format={"type": "json_object"}` ensures clean JSON without markdown fences |
| **JSON parsing** | LangChain `JsonOutputParser` (agent) / `json.loads` (gemini_client) | Agent uses `JsonOutputParser` so failures surface as structured exceptions rather than silent empty dicts |
| **CAS model** | `intfloat/multilingual-e5-base` (reused from Module 1 E5 singleton) | Zero additional model loading cost; the same 768-dim unit vectors enable cosine similarity comparison against approved captions |
| **HCS algorithm** | Pure Python (no AI dependency) | Deterministic 6-rule checker always executes; satisfies FR3.30 (always-available fallback); no network calls, no model loading |
| **Cultural research** | SerpAPI (`google-search-results` package) → curated template fallback | Live search enriches the Groq prompt with current traveler behavior; curated templates covering all 4 UC-3.1 data points ensure quality output even without SerpAPI access |
| **Visual guides** | `gemini_client.get_platform_guides(market)` — in-memory dict | Market × platform curated visual direction (Korea/Japan/USA × Instagram/TikTok/Facebook/Naver); no Groq call needed for guides — reduces RPM consumption |
| **Naver Blog content** | Hardcoded Korean-language templates in `content.py` | Naver content requires long-form editorial Korean writing (1,500+ chars with subheadings and embedded maps) which the 3-platform agent cannot produce reliably; curated templates ensure consistent quality |
| **Spring Boot orchestration** | `ContentGenerationService`, `CreativeDirectionService`, `ComplianceAnalysisService` | Each service reads from and writes to the same DB tables, creating a clean dependency chain: 3.1 content → 3.2 creative → 3.3 compliance, enforced by the `approval_status` gate |
| **Revision tracking** | `ComplianceRevisionHistory` table + `revisionNumber` field | Each resubmission creates a new `ComplianceEvaluationResult` row and a `ComplianceRevisionHistory` entry linking back to the original. Enables audit trail of iterative caption improvements |
| **Content framework** | `"SOR — Stimulus-Organism-Response"` | Theoretical marketing framework embedded as a constant; Stimulus (the hook), Organism (the psychological processing by the traveler), Response (the CTA and booking intent) |
| **Database** | PostgreSQL 16 (shared with Modules 1 and 2) | `tbl_localized_promotional_content` and `tbl_creative_direction_output` are queried by `ComplianceAnalysisService` to enrich the OMCS pipeline |
| **Containerization** | Docker Compose — same `fastapi-sbert` container (port 8000) as Module 1 | Module 3 routes (`/internal/content`, `/internal/creative`, `/internal/compliance`) are registered in the same `app.main` alongside Module 1 classification routes |
| **Observability** | MDC error codes (`MOD31_*`, `MOD32_*`, `MOD3_*`), `X-Trace-Id` propagation, `ContentGenerationLog` + `CreativeDirectionLog` audit tables | Every generation, approval, and evaluation event carries a structured log code; revision numbers provide compliance audit trail without log access |
