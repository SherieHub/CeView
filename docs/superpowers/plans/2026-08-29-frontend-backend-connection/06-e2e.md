# Slice 5 — End-to-End Journey

**Depends on:** all four slices merged ([`02-module-2.md`](02-module-2.md) …
[`05-module-3.md`](05-module-3.md)).

The spec's verification section requires a Playwright walk of
login → onboarding → dashboard → studio → analytics against the real stack. This file
implements it.

**Starting state.** Every spec in `e2e/tests/` is currently scaffolding — `test.describe.skip`
wrapping `test.fixme()` bodies with no assertions. Nothing in the e2e suite exercises the
app today, so "the e2e tests pass" currently means "the e2e tests do not run".

**Known config bug.** `e2e/playwright.config.ts` defaults `baseURL` to
`http://localhost:3000`, but `frontend/vite.config.ts` serves on **3001**. Every e2e run
without an explicit `E2E_BASE_URL` targets a port with nothing on it. Task 26 fixes this.

```ts
import { test } from '@playwright/test';

export const API_BASE = process.env.E2E_API_BASE_URL || 'http://localhost:8080';

/** Seeded demo operator — SEED_CREDENTIALS.md. */
export const SEED_OPERATOR = {
  email: 'ramon.delacruz@ceview.local',
  password: 'MoalboalDive2024!',
};

/**
 * Skips a spec when the backend isn't running, matching the contract tests'
 * behaviour so a developer without Docker sees skips rather than failures.
 */
export async function requireBackend() {
  try {
    const res = await fetch(`${API_BASE}/api/auth/login`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(SEED_OPERATOR),
      signal: AbortSignal.timeout(3000),
    });
    test.skip(res.status >= 500, `Backend unhealthy at ${API_BASE}`);
  } catch {
    test.skip(true, `No backend at ${API_BASE} — run: cd backend && docker compose up -d`);
  }
}
```

## Task 27: The full-journey spec

**Files:**

- Create: `e2e/tests/journey.spec.ts`

- [ ] **Step 1: Write the journey spec**

Create `e2e/tests/journey.spec.ts`:

```ts
import { test, expect } from '@playwright/test';
import { requireBackend, SEED_OPERATOR } from './support/stack';

/**
 * The connection spec's end-to-end verification: every wired screen renders
 * real backend data for a seeded operator.
 * Plan: docs/superpowers/plans/2026-08-29-frontend-backend-connection/06-e2e.md
 *
 * Deliberately asserts on DATA, not layout — a screen that renders its shell
 * but no backend rows is exactly the failure this suite exists to catch.
 */
test.describe('authenticated journey against the real stack', () => {
  test.beforeEach(async () => {
    await requireBackend();
  });

  test('logs in and lands on a dashboard with seeded alerts', async ({ page }) => {
    await page.goto('/');
    await page.getByLabel(/email/i).fill(SEED_OPERATOR.email);
    await page.getByLabel(/password/i).fill(SEED_OPERATOR.password);
    await page.getByRole('button', { name: /sign in/i }).click();

    await expect(page).toHaveURL(/\/dashboard/);

    // Real alerts, not an empty shell.
    const feed = page.getByTestId('alert-feed');
    await expect(feed).toBeVisible();
    await expect(feed.getByRole('article').first()).toBeVisible();

    // The ai-down banner must be absent when the stack is healthy.
    await expect(page.getByText(/forecasting is temporarily unavailable/i)).toHaveCount(0);
  });

  test('market radar drawer shows real economic values, never undefined', async ({ page }) => {
    await login(page);
    await page.getByTestId('alert-feed').getByRole('article').first().click();
    await page.getByRole('button', { name: /view market/i }).first().click();

    const drawer = page.getByRole('dialog');
    await expect(drawer).toBeVisible();

    await drawer.getByRole('tab', { name: /purchasing power/i }).click();
    // Task 10's mapped fields — a regression here renders "undefined" or "NaN".
    await expect(drawer).not.toContainText('undefined');
    await expect(drawer).not.toContainText('NaN');

    await drawer.getByRole('tab', { name: /seasonal/i }).click();
    // yoyRatio has no producer; the explicit state is correct, a blank is not.
    await expect(
      drawer.getByText(/YoY (\d|ratio not available)/i).first(),
    ).toBeVisible();
  });

  test('performance screen renders KPIs computed from real campaign records', async ({ page }) => {
    await login(page);
    await page.getByRole('link', { name: /performance/i }).click();

    await expect(page.getByTestId('kpi-roas')).toBeVisible();
    await expect(page.getByTestId('kpi-roas')).not.toHaveText(/^\s*$/);
    await expect(page.getByTestId('kpi-roas')).not.toContainText('NaN');
  });

  test('content studio either generates captions or names the missing dependency', async ({ page }) => {
    await login(page);
    await page.getByRole('link', { name: /content/i }).click();

    // Both outcomes are correct depending on whether GROQ_API_KEY is set.
    // What must never happen is a blank panel with a console-only error.
    const captions = page.getByTestId('caption-matrix');
    const setupRequired = page.getByText(/setup required/i);
    await expect(captions.or(setupRequired)).toBeVisible({ timeout: 30_000 });

    if (await setupRequired.isVisible()) {
      await expect(page.getByText(/GROQ_API_KEY/)).toBeVisible();
    }
  });
});

async function login(page: import('@playwright/test').Page) {
  await page.goto('/');
  await page.getByLabel(/email/i).fill(SEED_OPERATOR.email);
  await page.getByLabel(/password/i).fill(SEED_OPERATOR.password);
  await page.getByRole('button', { name: /sign in/i }).click();
  await expect(page).toHaveURL(/\/dashboard/);
}
```

## Task 28: Wire the journey into CI

**Files:**

- Modify: `.github/workflows/e2e.yml`

- [ ] **Step 1: Read the current workflow**

```bash

```

Note whether it already starts Docker services. If it runs Playwright without a backend,
the new spec will skip — which is safe, but gives no coverage.

- [ ] **Step 2: Start the stack before the Playwright step**

Add a service startup step before the test run:

```yaml
      - name: Start backend stack
        run: |
          cd backend
          # --no-deps is REQUIRED: spring-boot declares
          #   depends_on: fastapi -> condition: service_healthy
          # so a plain `up spring-boot` would also start fastapi-sbert and block
          # on its ~1.1GB E5 encoder download. --no-deps skips that; the app
          # degrades on AI calls, which the journey spec already treats as valid.
          docker compose up -d postgres
          docker compose up -d --no-deps spring-boot
          # Spring Boot runs Flyway on boot; wait for the seeded login to answer
          # rather than a fixed sleep, which flakes on slower runners.
          for i in $(seq 1 60); do
            if curl -sf -o /dev/null -X POST http://localhost:8080/api/auth/login \
              -H 'Content-Type: application/json' \
              -d '{"email":"ramon.delacruz@ceview.local","password":"MoalboalDive2024!"}'; then
              echo "backend ready"; exit 0
            fi
            sleep 5
          done
          echo "backend did not become ready"; docker compose logs spring-boot; exit 1
```

Start only `postgres` and `spring-boot`, and note the `--no-deps` above is not optional —
`spring-boot`'s `depends_on` requires `fastapi` to be *healthy*, so without it Compose
starts the sbert image and blocks on its ~1.1GB E5 encoder download. The AI services are
deliberately omitted: the journey spec already treats a missing `GROQ_API_KEY` as a valid
outcome. This gives CI real coverage of modules 2 and 4 without a ten-minute image pull.

The same `--no-deps` trick is useful locally whenever you only need modules 2 and 4.

## Closing note on the accepted tradeoff

The spec declined mocked-fetch unit tests and the static route-inventory check, so this
plan's only guard against path drift is the contract suite plus this journey — both of
which need a running backend. Task 28 gives CI a backend for modules 2 and 4; modules 1
and 3 remain unguarded in CI because their AI dependencies are too heavy for the runner.

If drift lands in module 1 or module 3 despite this plan, the cheapest fix is the
route-inventory check that was declined: a test that greps the Spring controllers for
`@RequestMapping` paths and asserts every path in `apiClient.ts` appears among them. It
needs no backend and would run on every PR. Revisit it then.
