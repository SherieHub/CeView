# Remove Synthetic Fallbacks — Design Spec

**Date:** 2026-08-30
**Status:** Approved, ready for planning
**Predecessor:** [`2026-08-29-frontend-backend-connection-design.md`](2026-08-29-frontend-backend-connection-design.md)

## Goal

A co-developer reading this repository must be able to answer "is this data real?"
from the source alone, without reasoning about a flag, an environment variable, or
which branch of a ternary executed.

Concretely: every value rendered in the CeView UI is either read from PostgreSQL,
computed by a documented formula over PostgreSQL rows, or generated by one of the
implemented AI models. Where a dependency is unavailable, the UI states that it is
unavailable and why. Nothing is fabricated to keep a screen looking complete.

## Non-goals

- Building the missing spec-C endpoints (`/api/posts`, `/api/platform-connections`,
  `/api/workspace/*`). Those screens declare themselves unbuilt instead.
- Building Module 1's `AnalysisStep` (Task 21 of the predecessor plan, still blocked).
- Fixing `MOD31_CAPTION_AGENT_FAILED` ("missing platform 'tiktok'"). This spec makes
  that failure visible and unmaskable; repairing the caption agent's prompt is
  separate work.
- Any change to the PES formula, uniqueness scoring, or forecasting algorithms.

## Background

An audit of `.worktrees/frontend-backend-connection` found synthetic data at three
levels. The frontend fixture layer is honest (a compile-time flag, default off) but
still present in the tree. The backend is not: several AI endpoints return canned
text with HTTP 200 when their model is unreachable, and one returns canned text on
the success path.

The immediate trigger is a configuration defect that made this invisible.
`docker-compose.yml` defaults `GROQ_MODEL` to `llama-3.3-70b-versatile`, which Groq
decommissioned. The key still authenticates, so Groq answers `404 model_not_found`,
the fallback fires, and the application appears to work while producing no real model
output at all.

## Decisions

| # | Decision | Rationale |
|---|---|---|
| D1 | Delete fallbacks; do not gate them behind a flag | A reader must not have to reason about a flag to know what they are looking at |
| D2 | Full cause detail reaches the browser | Internal tool behind JWT; diagnostic value outweighs disclosure risk |
| D3 | Screens with no backend route render `NotImplementedPanel` | Honest, no new backend work, no seed data mistakable for real data |
| D4 | External-data failures fall back to last-known-good, never synthesis | PyTrends 429s often; stale real data beats both fabrication and a dark dashboard |
| D5 | Naver removed as a generation and publish target | Operator decision; see D6 for the boundary |
| D6 | Naver survives as something the AI may *recommend* | `_PLATFORM_MAP` and `cultural_research` describe where Korean tourists are — real analysis. Deleting them would make the AI's advice wrong to satisfy a code cleanup |
| D7 | `Literal` types are the primary defense; the grep guard is backup | A guard people can delete is weaker than a shape that cannot represent the violation |

## Section 1 — The unavailability contract

One wire shape, three services, no translation loss.

**Format.** HTTP 503 when a dependency is unavailable; HTTP 424 when a required
upstream input is absent (empty metrics, empty core services).

```json
{
  "code": "MOD31_LLM_UNAVAILABLE",
  "message": "Caption generation is unavailable.",
  "dependency": "groq",
  "cause": "GROQ_MODEL 'llama-3.3-70b-versatile' returned 404 model_not_found",
  "stage": "fastapi-sbert/caption_agent"
}
```

`cause` is written once, at the site that knows why, and is never re-worded on the
way up. `stage` gains a hop at each boundary so the chain is visible.

**FastAPI (both services).** A shared `DependencyUnavailable(code, dependency, cause,
stage)` exception plus one app-level exception handler per service that renders the
shape. `app/errors.py` already holds the code registry; those codes stop being
log-only warnings and become the thrown value. Its three orphaned
`MOD3_COMPLIANCE_GEMINI_*` entries are deleted — `omcs_analysis.py` never uses them.

**Spring.** `AIInferenceGatewayService` gains a passthrough: a FastAPI 503 carrying
this body is re-emitted verbatim rather than collapsed into `ai_service_unreachable`.

**Frontend.** `apiError.ts`'s `ApiError` gains `dependency`, `cause`, `stage`.
`ApiErrorPanel` renders them in its existing monospace `<dl>`. The hardcoded
`MISSING_DEPENDENCY_CODES` allowlist is replaced by presence of `dependency`, which
is more robust than enumerating codes.

**Reference implementation.** `routers/omcs_analysis.py:72-79` already does exactly
this — raises 503 with a code, no fallback. It is the model for every site below.

correct, but avoidably alarming.

## Section 2a — Remove Naver entirely

**Boundary (D6).** Remove Naver as a generation and publish target. Keep it as
something the AI may recommend.

**No schema change required** — no CHECK constraint, no enum, no seed rows reference
Naver.

**Deleted:**

| Layer | Change |
|---|---|
| `fastapi-sbert/app/routers/content.py` | `_NAVER_OPTIONS` :52, `_NAVER_OPTION_NAMES` :64, injection block :177-182, naver keys in docstrings :140-147 and :200-205 |
| `fastapi-sbert/app/services/gemini_client.py` | `NAVER` prompt rule :220, the `- naver: 2 options…` instruction :227, `"naver"` guide arrays at :622, :669, :699, :729 |
| `spring-boot/.../module3/dto/ContentDtos.java` | `PlatformContentDto naver` :59, docs :10 and :39 |

| `spring-boot/.../module3/submodule31/LocalizedPromotionalContent.java` | Doc :11 — "four rows" becomes three |
| `frontend/types.ts:78` | `PlatformId` loses `'naver'`, leaving instagram / tiktok / facebook |
| `frontend/components/module-3/3.1-content-studio/AIContentMatrixPanel.tsx` | Tab :18, 5000-char limit :11, curated-template disclaimer :189-191 |
| `frontend/components/module-3/3.1-content-studio/PublishComposer.tsx` | Label :6, `CONNECTED` entry :7 |

**Kept, deliberately:** `routers/report.py:80-81` `_PLATFORM_MAP`,
`services/cultural_research.py:44-66`, `routers/creative.py`'s FR3.16
platform-recommendation docstring, `agents/pes_report_agent/prompt.py`'s CPC examples.

**Type narrowing is the safety net.** Removing `'naver'` from `PlatformId` makes
`tsc` enumerate every remaining frontend reference. On the backend, `ContentDtos`
losing the field means `ContentGenerationService` will not compile until :154 goes.
Neither codebase can be half-migrated silently.

**Migration `V24__module3_drop_naver_content.sql`** (data only):
`DELETE FROM tbl_localized_promotional_content WHERE platform = 'naver'`. Without it,
historical rows still surface through any query that does not filter — and they are
the hardcoded Korean text.

**Tests updated:** `AssetsLinksStep.test.tsx:65`,
`3.1-content-studio/testFixtures.ts:39`, `PreviouslyPublished.test.tsx:14`. That
file's :43-50 assertion ("no Naver tab") becomes trivially true and is simplified
rather than left as a misleading guard.

## Section 3 — Tier B: delete the frontend fixture layer

**The flag goes first.** `USE_FIXTURES` and every ternary in
`frontend/services/apiClient.ts` are removed; each method collapses to its
`request(...)` half. The `delay()` helper goes with it. `VITE_USE_FIXTURES` is
stripped from `frontend/.env`, `frontend/.env.example`, and `frontend/vite-env.d.ts`
so no stale switch survives. (`render.yaml` never set it.)

**`frontend/services/fixtures/` is deleted outright** — all 11 modules plus
`README.md`, and `frontend/services/apiClient.fixtures.test.ts`. Three things inside
it are not fixtures and are rehomed first:

- `OMCS_RUBRIC_LABELS` → `components/module-3/3.1-content-studio/omcsRubric.ts`.
  Display labels for the seven rubric keys the model returns — UI vocabulary, not data.
- `demoBusiness.ts`'s `DEMO_BUSINESS` → `components/module-1/onboarding/devSeed.ts`,
  exported as `DEV_SEED_DRAFT`. The rename is the hardening: `DEMO_BUSINESS` reads
  like a tenant, `DEV_SEED_DRAFT` reads like what it is. Both consumers
  (`BasicInfoStep.tsx:101` dev-only button, `App.tsx:44` preview route) are already
  `import.meta.env.DEV`-gated and stay that way.
- `profile.ts`'s `DEMO_PROFILE` → a local const inside `App.tsx`'s `devPreviewRoutes`
  block, so no production module can import it.

**`DEFAULT_CAMPAIGN_INPUT` is not rehomed — it is zeroed.** It seeds `IngestionForm`
with 95,000 impressions / PHP 4,000 spend / PHP 35,000 revenue. Its comment argues
this is "legitimate starting form state", but a developer who clicks Analyze without
editing writes invented numbers into `tbl_campaign_records`, where they feed a real
PES score and a real AI report — the exact confusion this spec removes, laundered
through the database. The form ships with empty fields and required-field validation.

**`<NotImplementedPanel>`** — a new sibling of `ApiErrorPanel` in
`frontend/components/shared/`. Takes the missing endpoint and renders it plainly:

> **Not built yet** — Published posts needs `GET /api/posts`, which has no backend
> route. Tracked as spec-C deferred work.

It replaces `MOCK_POSTS` in `ContentStudioView`'s published board and
`PreviouslyPublished`, `MOCK_CONNECTIONS` in Settings → Platforms, `MOCK_MEMBERS` in
Settings → Workspace, and `MOCK_POST_METRICS` in `PostAnalyticsModal`. The
corresponding `apiClient` methods (`posts.*`, `connections.*`, `workspace.*`) are
deleted rather than left pointing at 404s — a method that cannot succeed is worse
than no method.

**Type cleanup this unblocks:** `WorkspaceMemberFixture` disappears, resolving the
`types.ts:89` / `apiClient.ts:321` comment about two irreconcilable member shapes.
`types.ts`'s `WorkspaceMember` survives as the single definition, unused until the
endpoint lands.

**Test fallout.** `apiClient.fixtures.test.ts` deleted. `apiClient.auth.test.ts`,
`profileContext.test.tsx`, `BusinessProfileSettings.test.tsx`,
`connectionsStore.test.tsx`, `PreviouslyPublished.test.tsx`,
`PostAnalyticsModal.test.tsx` and the module-3 suites currently import fixtures for
their arrange step; they move to locally-declared doubles in `__fixtures__` files
adjacent to each test. Test doubles inside test files are fine — the problem was only
ever that production code could import them.

## Section 4 — Tier C: last-known-good, never synthetic

**Provenance becomes a persisted column.** `tbl_trend_fetch_job.source` already
records `'pytrends'` or `'stub'`, but `tbl_market_signal_record` has no `source`
column — a stub trend index aggregated into a signal record loses its synthetic
origin permanently. Today there is no way to tell which persisted rows are real, so
last-known-good is unimplementable without fixing this first.

**`V22__module2_signal_provenance.sql`** adds `source VARCHAR(20) NOT NULL` and
`source_fetched_at TIMESTAMPTZ` to `tbl_market_signal_record`, carried through from
the originating `tbl_trend_fetch_job`.

**`V23__module2_purge_synthetic_signals.sql`** deletes signal records traceable to a
`tbl_trend_fetch_job` with `source = 'stub'`, and the `tbl_forecast_result` /
`tbl_market_score` rows derived from them. Records with no traceable job are marked
`source = 'unknown'` and treated as untrusted by the reader. Skipping this would let
last-known-good faithfully resurrect the stub data being removed.

**PyTrends.** `fastapi-transformer/app/services/trend_service.py`: `_STUB_BASE` :59,
`_STUB_SERIES` :71 and `_stub_result()` are deleted. The service raises
`DependencyUnavailable(dependency="pytrends", cause=<import error | 429 | timeout>)`;
the optional-import `try/except` at :41-49 stops swallowing and records the reason.
`TrendFetchSchedulerService` catches it, writes **no** signal record, and marks the
fetch job failed with the cause.

**Reading, on the forecast side.** `EnrichedSequenceBuilder` filters to
`source = 'pytrends'` and returns the newest real records with their `aggregated_at`:

| State | Behaviour |
|---|---|
| Fresh real data | Normal forecast |
| Stale real data (> 48h) | Forecast runs; response carries `dataAsOf` and `stale: true` |
| No real data | 503 `MOD22_NO_MARKET_DATA` with the last ingestion failure's cause |

**GDP / forex.** `ExternalMarketDataClient`: `gdpTrendFallback()` :284,
`forexTrendFallback()` :295, and the fallback constant maps :68-72 are deleted. On a
World Bank or currency-CDN failure the client reads the newest
`tbl_market_economic_trend` row for that market — the query the table was designed
for, already documented in `V11` at :13 — and returns it with its `fetched_at`. No
prior row means the field is `null` and the market's economic panel says so.

**Seasonality.** The inline 2-sigma spike fallback at
`MarketDataIngestionService.java:174` is deleted. `spike_indicator` becomes nullable;
the UI omits the spike chip rather than guessing it.

**`<StaleDataBanner>`** — sibling to `ApiErrorPanel` and `NotImplementedPanel`:

> **Data is 6 days old.** Last successful PyTrends fetch: 2026-08-24. Latest attempt
> failed — `429 Too Many Requests`.

`Market` gains `dataAsOf: string | null` and `dataStale: boolean`. The dashboard
renders the banner above the market list whenever `dataStale`. Staleness is a
*degraded* state, visually distinct from `ApiErrorPanel`'s failure state — the numbers
below it are real, just old, and conflating the two would train people to ignore both.

**The staleness threshold is 48 hours**, matching the scheduler cadence, defined in
one constant so it is not re-derived in three places.

## Section 5 — Making it stick

**1. Make fallbacks unrepresentable.** Every AI response model's `source` becomes
`Literal["groq"]` (or `["gemini"]`) instead of `str = "fallback"`. Returning canned
content is then a Pydantic `ValidationError` at runtime, caught by the service's own
tests, not a policy violation someone might notice in review. On the Spring side,
`ContentDtos`' `source` becomes an enum with no `FALLBACK` constant, so reintroducing
`buildRuleBasedReport` would also require widening the enum — a visible, arguable
diff. This is the primary defense.

**2. Negative-path contract tests — the actual proof.** The existing 13 contract
tests assert success shapes. A new
`frontend/tests/contract/unavailable.contract.test.ts` runs the stack with
`GROQ_API_KEY` deliberately unset and asserts every AI endpoint returns **503 with a
populated `dependency` and `cause`**, never 200. Today that configuration returns
cheerful fake captions. Driven by a compose override and wired into
`.github/workflows/e2e.yml`, which already builds a real stack.

**3. The guard script.** `scripts/no-synthetic-data.mjs`, run by all six CI
workflows. It matches **identifiers, not prose** — matching the word "fallback" would
fire on legitimate comments and get switched off. Banned identifiers:

```
_mock_captions          _fallback_captions      _FALLBACK_SERVICES
_NAVER_OPTIONS          _NAVER_OPTION_NAMES     _creative_fallback
_FALLBACK_PAYLOAD       _FALLBACK_REPORT        _FALLBACK_EVALUATION
_fallback_report        _STUB_BASE              _STUB_SERIES
_stub_result            ml_stubs                buildRuleBasedReport
buildOfflinePesAnalysisFallback                 gdpTrendFallback
forexTrendFallback      VITE_USE_FIXTURES       services/fixtures
MOCK_  (frontend, non-test files only)
```

`scripts/synthetic-data-allowlist.json` requires a written reason per entry.
Currently one entry: `PESComputationService`'s corrected comment.

**4. `fastapi-transformer/app/services/ml_stubs.py` is deleted.** It has zero
importers, and a file of mock forecast outputs sitting in the tree is the single most
misleading artifact for a co-developer skimming the repo.

**5. Provenance e2e.** One Playwright spec that logs in as a seeded operator, visits
all four modules, and asserts none of the known canned strings appear in the DOM —
the Naver Korean captions, `"resort stay"`, `"Analysis unavailable — AI agent is
offline."` It is the end-to-end statement of the guarantee.

**Unit tests.** `ApiErrorPanel` rendering `dependency`/`cause`/`stage`;
`NotImplementedPanel`; `StaleDataBanner` at the 48h boundary;
`EnrichedSequenceBuilder`'s three outcomes; `MarketDataIngestionService` writing no
record on fetch failure.

**Docs.** A `RUNNING.md` section — "Why a screen says unavailable" — mapping each
`dependency` value to its fix. A `.claude/CLAUDE.md` line making the no-fallback rule
explicit for future sessions.

## Sequencing

Each step leaves the tree working.

1. Section 1 contract + configuration fixes — nothing deleted; everything gains the new error shape
2. Migrations V22-V23 + provenance plumbing — Tier C's foundation
3. Tier A deletions + `Literal` types
4. Naver removal (2a) — type narrowing does the finding
5. Tier B fixture deletion + `NotImplementedPanel` / `StaleDataBanner`
6. Guard script, negative-path contract tests, provenance e2e, docs

Tier A before Tier C's provenance work would blank Module 2 with no staleness story
to soften it, which is why the migrations come second.

## Risks

| Risk | Mitigation |
|---|---|
| A misconfigured environment now visibly fails where it previously appeared to work | Intended. The Section 2 configuration fixes land in the same phase so the common case works |
| PyTrends 429s blank a market that has never been ingested | Accepted (D4). Last-known-good covers every market with at least one successful fetch; `MOD22_NO_MARKET_DATA` names the cause for the rest |
| Removing Naver narrows Module 3 for the Korea market, where Naver Blog is the dominant channel | Operator decision (D5). D6 keeps the AI able to recommend Naver as a channel |
| V23 deletes forecast history derived from stub data | Intended. That history is fabricated. The migration logs affected row counts |
| The guard script gets disabled | Mitigated by D7 — `Literal` types fail without it |
